# Data Dictionary

## Описание датасета

Для анализа процесса закупок был создан синтетический датасет из 5 000 закупочных заявок.
Данные сгенерированы специально для проекта и не являются реальными данными компании.

Датасет содержит **5 000 закупочных заявок** и используется для анализа процесса их обработки.

Каждая строка соответствует одной закупочной заявке.

Данные позволяют анализировать:

- тип закупки;
- сумму заявки;
- подразделение-инициатор;
- длительность обработки;
- количество возвратов и уточнений;
- способ передачи заявки;
- тип маршрута;
- итоговый статус.

---

## Структура данных

| Поле | Тип данных | Описание |
| :--- | :--- | :--- |
| `request_id` | `INTEGER` | Уникальный идентификатор заявки |
| `purchase_type` | `TEXT` | Тип закупки |
| `amount` | `REAL` | Сумма закупки |
| `department` | `TEXT` | Подразделение, инициировавшее закупку |
| `request_date` | `DATE` | Дата создания заявки |
| `total_time_hours` | `REAL` | Общее время обработки заявки в часах |
| `returns_count` | `INTEGER` | Количество возвратов заявки на доработку |
| `clarifications_count` | `INTEGER` | Количество запросов на уточнение информации |
| `transfer_method` | `TEXT` | Способ передачи заявки между участниками |
| `route_type` | `TEXT` | Тип маршрута обработки заявки |
| `final_status` | `TEXT` | Итоговый статус заявки |

---

## Описание полей

---

### `request_id`

**Уникальный идентификатор закупочной заявки.**

Используется для однозначной идентификации заявки при проведении анализа.


---

### `purchase_type`

**Тип закупки.**

Определяет дальнейший маршрут согласования заявки.


**Допустимые значения:**

| Значение | Описание |
| :--- | :--- |
| `Простая` | Стандартная закупка без дополнительных согласований |
| `IT` | Закупка IT-оборудования или программного обеспечения |
| `Юридическая` | Закупка, требующая юридической проверки договора |

---

### `amount`

**Сумма закупки.**

Используется для анализа распределения заявок по стоимости.


**Формат:** Положительное число с двумя десятичными знаками.

---

### `department`

**Подразделение, инициировавшее закупку.**

Используется для сравнения характеристик процесса между подразделениями.

---

### `request_date`

**Дата создания закупочной заявки.**

Используется для анализа распределения заявок во времени и расчёта сезонности.


**Формат:** `YYYY-MM-DD`

---

### `total_time_hours`

**Общее время обработки заявки в часах.**

Показатель используется для:

- анализа длительности процесса;
- сравнения времени обработки заявок разных типов;
- оценки эффективности маршрутов.

---

### `returns_count`

**Количество возвратов заявки на доработку.**

Позволяет оценить влияние повторной обработки на общее время прохождения заявки и качество заполнения.


---

### `clarifications_count`

**Количество запросов на уточнение информации по заявке.**

Используется для анализа связи между количеством уточнений и временем обработки.


---

### `transfer_method`

**Способ передачи заявки между участниками процесса.**


**Допустимые значения:**

| Значение | Описание |
| :--- | :--- |
| `Email` | Передача заявки по электронной почте (ручной процесс) |
| `Система` | Передача заявки через единую систему управления заявками (автоматизированный процесс) |

---

### `route_type`

**Тип маршрута, по которому проходит заявка.**


**Допустимые значения:**

| Значение | Описание |
| :--- | :--- |
| `Стандартный` | Заявка проходит заранее определённую последовательность согласований |
| `Нестандартный` | В процессе требуется дополнительный или изменённый этап согласования |

---

### `final_status`

**Итоговый статус заявки на момент формирования датасета.**


**Допустимые значения:**

| Значение | Описание |
| :--- | :--- |
| `Одобрена` | Заявка прошла все необходимые этапы согласования и одобрена |
| `Отклонена` | Заявка была отклонена в процессе согласования |
| `В процессе` | Обработка заявки ещё не завершена |
