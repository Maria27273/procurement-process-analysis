# Business Requirements

## 1. Назначение

Business Requirements определяют, каких результатов необходимо достичь в рамках улучшения процесса закупок.

Требования сформированы на основе проблем, выявленных при анализе текущего процесса.

## 2. Business Requirements

| ID | Business Requirement |
|---|---|
| BR-01 | Централизовать процесс обработки закупочных заявок |
| BR-02 | Повысить прозрачность процесса обработки заявок |
| BR-03 | Снизить количество ошибок при обработке закупочных заявок |
| BR-04 | Сократить количество ручных операций в процессе |
| BR-05 | Обеспечить управляемую маршрутизацию закупочных заявок |
| BR-06 | Обеспечить сохранность информации об истории обработки заявок |
| BR-07 | Сократить время обработки закупочных заявок |
| BR-08 | Обеспечить возможность анализа эффективности процесса закупок |

## 3. Критерии приёмки

| ID | Acceptance Criteria |
|---|---|
| BR-01 | Для каждой закупочной заявки существует единое место её создания и обработки |
| BR-02 | Участник процесса может определить текущий статус заявки без обращения к другим участникам |
| BR-03 | Заявка не может перейти к следующему этапу при отсутствии обязательной информации |
| BR-04 | Передача заявки между участниками не требует ручной пересылки по электронной почте |
| BR-05 | Для каждого типа закупки определён соответствующий маршрут обработки |
| BR-06 | Для каждой заявки доступна история её основных изменений и этапов обработки |
| BR-07 | Среднее время обработки заявок после внедрения решения ниже базового значения, определённого по данным AS-IS |
| BR-08 | Данные по обработанным заявкам могут использоваться для расчёта показателей процесса |

## 4. Ограничения

Business Requirements описывают ожидаемый бизнес-результат и не определяют конкретный способ технической реализации решения.

Детальное поведение системы и условия выполнения отдельных функций будут описаны в функциональных требованиях.
