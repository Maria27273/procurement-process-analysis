# Non-Functional Requirements

## 1. Производительность

NFR-01. Все основные страницы и данные заявок должны загружаться не дольше 3 секунд при штатной нагрузке.

NFR-02. Система должна сохранять время отклика не более 3.6 секунд при одновременной работе 100 пользователей.

## 2. Доступность

NFR-03. Время доступности системы в рабочие часы (с 9:00 до 18:00 МСК) должно составлять не менее 99.5%, без учёта плановых остановок.

NFR-04. Плановые технические работы с остановкой системы — не более 4 часов в месяц, с обязательным уведомлением пользователей за 24 часа.

NFR-05. При сбоях и перезапусках системы все сохранённые и отправленные заявки должны быть восстановлены. Потеря несохранённых черновиков допускается.

## 3. Безопасность

NFR-06. Доступ к функциям и данным должен предоставляться строго в соответствии с ролью пользователя.

NFR-07. Все данные между клиентом и сервером должны передаваться по HTTPS. Пароли хранить только в зашифрованном виде. Неавторизованные запросы должны получать ошибку 401.

NFR-08. Система должна логировать все действия, меняющие состояние заявки: кто, когда и что сделал.

## 4. Целостность данных

NFR-09. Создание заявки должно блокироваться, если не заполнены все поля, отмеченные как обязательные.

NFR-10. Запрещено удалять статусы и маршруты, если они используются в существующих заявках (поддерживать ссылочную целостность).

NFR-11. Одновременное редактирование одной заявки разными пользователями должно блокироваться с выводом предупреждения.

## 5. Масштабируемость

NFR-12. Архитектура системы должна позволять горизонтальное расширение для работы с 10 000 пользователей и 1 000 000 заявок без изменения кода.

NFR-13. Новые типы закупок и маршруты согласования должны добавляться через административный интерфейс без остановки системы.

## 6. Аудит

NFR-14. Для каждого действия с заявкой сохранять: ID пользователя, дату и время (с точностью до секунды), IP-адрес, тип действия и значения статуса до и после изменения.

NFR-15. По данным аудита должна восстанавливаться полная хронология изменений любой заявки.

## 7. Удобство использования

NFR-16. Названия статусов, полей и действий должны быть едиными во всех разделах системы.

NFR-17. Все сообщения об ошибках должны быть на русском языке, без технического кода, с указанием причины ошибки и инструкции по её исправлению.

## 8. Интеграция

NFR-18. Система должна предоставлять REST API для интеграции с корпоративными системами (СЭД, бухгалтерия).

NFR-19. Данные заявок должны выгружаться в форматах CSV и JSON для анализа и отчётности.

## 9. Ограничения

NFR-20. Для входа в систему использовать единый корпоративный аккаунт (SSO / Active Directory). Создание локальных учётных записей запрещено.

NFR-21. Права доступа должны настраиваться через административный интерфейс по ролям, без перезапуска системы.
