# User Stories

## Модуль 1: Управление заявками (на основе UC-01, UC-02, UC-03)

### US-01. Создание черновика заявки

**Как** сотрудник,
**я хочу** создать новую закупочную заявку и сохранить её как черновик,
**чтобы** заполнять данные постепенно, без риска потерять информацию.

**Критерии приемки:**
1. На странице "Создание заявки" отображаются все обязательные поля (тип закупки, описание, сумма, подразделение).
2. Пользователь может прикрепить файлы (поддерживаемые форматы: PDF, DOC, DOCX, XLS, XLSX, JPG, PNG).
3. При нажатии "Сохранить" система проверяет обязательные поля. Если поля пустые — показывает ошибку и подсвечивает их.
4. При успешном сохранении система присваивает заявке уникальный номер и переводит её в статус "Черновик".
5. На экране появляется сообщение: "Заявка №[ID] успешно сохранена".

---

### US-02. Редактирование черновика

**Как** сотрудник,
**я хочу** редактировать заявку в статусе "Черновик" или "На доработке",
**чтобы** исправить ошибки или дополнить информацию перед отправкой.

**Критерии приемки:**
1. Пользователь открывает заявку и видит форму, заполненную ранее введёнными данными.
2. Пользователь может изменить все поля, кроме идентификатора заявки.
3. Пользователь может добавлять или удалять прикреплённые файлы.
4. При сохранении система проверяет обязательные поля и обновляет данные.
5. Редактирование недоступно для заявок в статусах: "На проверке", "На согласовании", "Согласована", "Отклонена".

---

### US-03. Отправка заявки на согласование

**Как** сотрудник,
**я хочу** отправить заполненную заявку на согласование руководителю,
**чтобы** запустить процесс закупки.

**Критерии приемки:**
1. Кнопка "Отправить на согласование" активна только для заявок в статусе "Черновик" или "На доработке".
2. Перед отправкой система проверяет все обязательные поля и наличие прикреплённых документов.
3. Если обязательные поля пустые, система блокирует отправку и показывает сообщение с перечнем незаполненных полей.
4. Система автоматически определяет маршрут согласования по типу закупки.
5. Заявка получает статус "На проверке".
6. Первый руководитель по маршруту получает уведомление (внутри системы и на email).

## Модуль 2: Согласование (на основе UC-04, UC-06)

### US-04. Принятие решения по заявке

**Как** руководитель,
**я хочу** просмотреть заявку и принять по ней решение (согласовать, отклонить или вернуть на доработку),
**чтобы** управлять процессом закупок в моём подразделении.

**Критерии приемки:**
1. В списке "Заявки на согласование" отображаются только заявки, ожидающие решения текущего руководителя.
2. При открытии заявки отображается полная информация, включая список прикреплённых документов (с возможностью скачать их).
3. Руководитель может выбрать одно из трёх решений: "Согласовать", "Отклонить" или "Вернуть на доработку".
4. При возврате или отклонении поле "Причина" становится обязательным для заполнения.
5. При согласовании комментарий необязателен (но поле для него есть).
6. После согласования заявка переходит на следующий этап маршрута. Если этап последний — заявка получает статус "Согласована".
7. После отклонения заявка получает статус "Отклонена".
8. После возврата заявка получает статус "На доработке".
9. Автор заявки получает уведомление о решении с указанием причины (если она была).

---

### US-05. Комментирование заявки

**Как** участник процесса согласования (руководитель, сотрудник),
**я хочу** оставлять комментарии к заявке,
**чтобы** обсуждать детали и уточнять вопросы прямо в системе, не прибегая к email.

**Критерии приемки:**
1. На странице заявки есть поле для ввода комментария и кнопка "Отправить".
2. Комментарий может быть оставлен на любом этапе обработки заявки.
3. После отправки комментарий сразу отображается в ленте комментариев (в хронологическом порядке).
4. Комментарий содержит: текст, имя автора, дату и время.
5. При отправке комментария уведомления другим участникам не отправляются (это опционально, просто обсуждение).

---

### US-06. Добавление нестандартного этапа согласования

**Как** администратор,
**я хочу** добавить дополнительный этап согласования вручную для конкретной заявки,
**чтобы** гибко управлять исключениями, не меняя системный маршрут для всех.

**Критерии приемки:**
1. На странице заявки у администратора есть кнопка "Добавить этап согласования".
2. Администратор указывает: роль согласующего, срок согласования и комментарий.
3. Добавленный этап встраивается в текущий маршрут заявки (становится следующим по порядку).
4. Основной маршрут для данного типа закупок не изменяется.
5. Ответственный согласующий получает уведомление о новой заявке на согласование.

## Модуль 3: Поиск и документация (на основе UC-07, UC-09, UC-11)

### US-07. Поиск заявок

**Как** пользователь,
**я хочу** искать заявки по параметрам (ID, тип, статус, дата),
**чтобы** быстро находить нужную информацию среди множества заявок.

**Критерии приемки:**
1. На странице "Заявки" доступна форма фильтрации.
2. Доступные фильтры: ID заявки (частичное совпадение), тип закупки (выбор из списка), статус (выбор из списка), дата создания (диапазон "от" и "до").
3. Поиск работает по логике "И" (все выбранные условия применяются одновременно).
4. Результаты отображаются в виде таблицы с сортировкой по дате создания (по умолчанию — новые сверху).

---

### US-08. Просмотр истории заявки

**Как** пользователь,
**я хочу** видеть полную историю изменений заявки,
**чтобы** понимать, кто, когда и зачем менял её статус.

**Критерии приемки:**
1. На странице заявки есть вкладка "История".
2. История отображается в хронологическом порядке (от старых событий к новым).
3. Для каждого события указано: дата/время, имя пользователя, действие, старый статус, новый статус, комментарий.
4. История доступна всем, у кого есть доступ к заявке.

---

### US-09. Просмотр и скачивание документов

**Как** пользователь,
**я хочу** просматривать и скачивать файлы, прикреплённые к заявке,
**чтобы** ознакомиться с документацией по закупке.

**Критерии приемки:**
1. На странице заявки отображается блок "Прикреплённые документы" со списком файлов.
2. Для каждого файла видно: название, размер, дата загрузки, иконка формата.
3. При клике на название файл скачивается на устройство.
4. Для PDF, JPG, PNG доступна кнопка "Просмотр" — документ открывается в новой вкладке.
5. Для DOC, XLS доступно только скачивание.

---

## Модуль 4: Завершение и аналитика (на основе UC-08, UC-10, UC-12)

### US-10. Приём заявки отделом закупок

**Как** сотрудник отдела закупок,
**я хочу** принять согласованную заявку и изменить её статус,
**чтобы** начать процедуру закупки и зафиксировать завершение согласования.

**Критерии приемки:**
1. В разделе "Заявки на исполнение" отображаются только заявки со статусом "Согласована".
2. Сотрудник ОЗ открывает заявку, проверяет документы и нажимает кнопку "Принять заявку".
3. Система меняет статус заявки на "Передана в отдел закупок".
4. Система фиксирует дату завершения обработки в истории.
5. Автор и руководитель получают уведомление: "Заявка передана в отдел закупок".

---

### US-11. Автоматическое уведомление о новых задачах

**Как** участник процесса (сотрудник, руководитель),
**я хочу** получать уведомления о действиях с заявками,
**чтобы** не пропускать свои задачи и реагировать на изменения вовремя.

**Критерии приемки:**
1. Уведомления приходят в двух каналах: внутри системы (в раздел "Уведомления") и на email.
2. Уведомления отправляются при следующих событиях:
   - поступление заявки на согласование (руководителю);
   - возврат заявки на доработку (автору);
   - отклонение заявки (автору);
   - согласование заявки (автору);
   - приближение срока обработки (ответственному).
3. Каждое уведомление содержит: номер заявки, описание действия и прямую ссылку на заявку.
