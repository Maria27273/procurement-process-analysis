# AS-IS Process Analysis

## 1. Описание текущего процесса

Процесс начинается с возникновения у сотрудника потребности в закупке.

Сотрудник самостоятельно формирует заявку и отправляет её руководителю по электронной почте. Руководитель получает заявку и проверяет её на корректность и полноту.

Если заявка заполнена некорректно или содержит недостаточно информации, она возвращается сотруднику на доработку. После внесения изменений сотрудник повторно отправляет заявку руководителю.

Если заявка заполнена корректно, руководитель определяет дальнейший маршрут в зависимости от типа закупки.

В зависимости от типа закупки к процессу могут подключаться IT, финансовый и юридический отделы. После прохождения необходимых согласований заявка передаётся в отдел закупок.

## 2. Основные этапы процесса

| Этап | Действие | Ответственный |
|---|---|---|
| 1 | Формирование заявки | Сотрудник |
| 2 | Передача заявки | Сотрудник |
| 3 | Проверка заявки | Руководитель |
| 4 | Доработка при необходимости | Сотрудник |
| 5 | Определение маршрута | Руководитель |
| 6 | Дополнительное согласование | Профильное подразделение |
| 7 | Передача согласованной заявки | Руководитель / ответственное подразделение |
| 8 | Обработка заявки | Отдел закупок |

## 3. Проблемы текущего процесса

### 3.1. Передача заявок по электронной почте

Электронная почта используется для передачи заявки между участниками процесса.

В результате информация о заявке может находиться в переписке разных сотрудников, а для получения актуальной информации необходимо искать соответствующие сообщения.

### 3.2. Ручная проверка заявок

Руководитель самостоятельно проверяет полноту и корректность заявки.

Если информация указана некорректно или её недостаточно, заявка возвращается сотруднику. После исправления она повторно проходит проверку.

Таким образом, наличие ошибок приводит к дополнительным циклам обработки.

### 3.3. Ручное определение маршрута

После проверки руководитель самостоятельно определяет, какие подразделения должны участвовать в согласовании.

Маршрут зависит от типа закупки, поэтому ошибка на этом этапе может привести к передаче заявки не тому участнику или к необходимости дополнительного согласования.

### 3.4. Отсутствие единого статуса заявки

В текущем процессе нет единого места, где участник может посмотреть актуальный статус заявки.

Для получения информации о состоянии заявки может потребоваться дополнительное обращение к другим участникам процесса.

### 3.5. Отсутствие централизованной истории

Информация о действиях участников хранится в рамках отдельных взаимодействий и переписки.

Это затрудняет восстановление полной истории обработки заявки и определение того, на каком этапе возникла задержка.

## 4. Узкие места процесса

На основе анализа текущего процесса выделены следующие потенциальные узкие места:

| Узкое место | Причина | Возможное последствие |
|---|---|---|
| Передача по email | Отсутствие единой системы | Потеря прозрачности процесса |
| Ручная проверка | Нет автоматической проверки данных | Повторная обработка заявок |
| Ручная маршрутизация | Маршрут определяется сотрудником | Ошибки и задержки |
| Отсутствие единого статуса | Нет централизованной системы | Сложность контроля |
| Отсутствие истории | Информация распределена между участниками | Сложность анализа процесса |

## 5. Вывод

AS-IS процесс содержит несколько этапов, выполняемых вручную, и предполагает передачу информации между участниками по электронной почте.

Основные потенциальные точки улучшения связаны с централизованной работой с заявками, маршрутизацией, контролем статуса и хранением истории обработки.

Выявленные проблемы будут использоваться на следующих этапах для формирования требований и разработки TO-BE процесса.
