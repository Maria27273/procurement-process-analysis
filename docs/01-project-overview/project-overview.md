# Project Overview

## Контекст

В компании процесс обработки закупочных заявок проходит через несколько подразделений. В зависимости от типа закупки в согласовании могут участвовать руководитель, отдел закупок, IT, финансовый и юридический отделы.

На текущий момент взаимодействие между участниками процесса в значительной степени осуществляется вручную. Сотрудник формирует заявку и направляет её руководителю по электронной почте, после чего заявка проходит необходимые проверки и согласования.

При увеличении количества заявок такой подход усложняет контроль процесса и увеличивает время их обработки.

## Проблема

Основные сложности текущего процесса связаны с отсутствием единого места для работы с заявками и большим количеством ручных действий.

В процессе возникают следующие проблемы:

* заявки передаются по электронной почте;
* информация о заявках хранится в разных местах;
* маршрут заявки определяется вручную;
* отсутствует единый контроль текущего статуса;
* при ошибках заявка возвращается на доработку и повторно проходит проверку;
* сложно отследить историю обработки заявки;
* увеличивается время обработки сложных и нестандартных закупок.

## Цель проекта

Разработать целевую модель процесса обработки закупочных заявок, которая позволит сократить количество ручных операций, повысить прозрачность процесса и уменьшить время обработки заявок.

## Задачи проекта

Для достижения цели необходимо:

1. Проанализировать текущий процесс обработки закупочных заявок.
2. Определить участников процесса и их зоны ответственности.
3. Выявить основные проблемы и узкие места текущего процесса.
4. Провести анализ данных по обработке заявок.
5. Сформировать бизнес-, функциональные и нефункциональные требования к целевому решению.
6. Разработать TO-BE модель процесса.
7. Описать основные сценарии взаимодействия пользователей с системой.
8. Разработать необходимые UML-модели и структуру данных.
9. Сформировать рекомендации по оптимизации процесса.

## Scope

### In Scope

В рамках проекта рассматриваются:

* создание и обработка закупочной заявки;
* проверка заявки;
* согласование заявки;
* маршрутизация заявки в зависимости от типа закупки;
* взаимодействие между участниками процесса;
* информирование участников о статусе заявки;
* хранение истории обработки;
* анализ эффективности процесса.

### Out of Scope

В рамках проекта не рассматриваются:

* поиск поставщиков;
* проведение оплаты;
* логистика и доставка;
* управление складскими запасами;
* детальная реализация интерфейса системы;
* техническая архитектура и выбор конкретного программного стека.

## Результат проекта

Результатом проекта должна стать целевая модель процесса закупок и набор требований к системе, которая позволит централизовать работу с заявками и автоматизировать основные этапы их обработки.

Дополнительно результаты анализа данных используются для определения наиболее проблемных участков процесса и обоснования предлагаемых изменений.
