# Impact Analysis

## Цель

Оценить, как предложенные изменения TO-BE процесса влияют на проблемы, выявленные при анализе текущего процесса и данных.

Поскольку данные проекта являются синтетическими, эффект автоматизации рассматривается как потенциальный, без количественного прогнозирования экономии.

## Связь проблем и решений

| Проблема AS-IS                                                   | Аналитическое подтверждение                                                                   | Решение TO-BE                                             | Потенциальный эффект                                      |
| ---------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | --------------------------------------------------------- | --------------------------------------------------------- |
| Возвраты существенно увеличивают время обработки                 | Заявки с возвратами: **48,06 ч**, без возвратов: **22,37 ч**                                  | Автоматическая проверка данных и единый процесс доработки | Снижение повторной обработки и времени прохождения заявки |
| Количество уточнений связано с увеличением длительности процесса | При увеличении количества уточнений растёт среднее время обработки                            | Проверка обязательных данных до отправки на согласование  | Снижение количества дополнительных уточнений              |
| Разные маршруты имеют значительную разницу во времени обработки  | `Manager → Procurement` — **9,35 ч**; `Manager → Finance → Legal → Procurement` — **57,50 ч** | Автоматическая маршрутизация по типу закупки              | Снижение задержек при передаче заявки между этапами       |
| Сложные закупки требуют прохождения нескольких подразделений     | IT и юридические закупки имеют более высокое среднее время обработки                          | Формализованные маршруты согласования                     | Повышение предсказуемости и прозрачности процесса         |
| Ручная передача заявки создаёт дополнительные точки ожидания     | В AS-IS используются ручные способы передачи заявки                                           | Централизованное согласование в системе                   | Сокращение ручных операций и повышение прозрачности       |


## Приоритет изменений

### Высокий приоритет

**1. Автоматическая маршрутизация**

Определение маршрута по типу закупки позволяет исключить ручную передачу заявки между подразделениями и сделать процесс более предсказуемым.

**2. Проверка данных до согласования**

Предварительная валидация позволяет выявлять некорректные или неполные данные до передачи заявки согласующим.

**3. Централизованная обработка возвратов**

Единый подпроцесс доработки позволяет стандартизировать повторную обработку заявки и сохранить историю изменений.

### Средний приоритет

**4. Автоматические уведомления**

Снижают зависимость процесса от ручного информирования участников.

**5. Централизованная история заявки**

Позволяет отслеживать текущий статус, участников и историю изменений.

## KPI для оценки результата

После внедрения автоматизации рекомендуется отслеживать следующие показатели:

| KPI                          |  AS-IS |
| ---------------------------- | -----: |
| Среднее время обработки      | 25,8 ч |
| Доля заявок с возвратами     | 13,22% |
| Среднее количество возвратов |   0,18 |
| Среднее количество уточнений |   0,63 |
| Доля заявок «В процессе»     |  7,72% |

Целевые значения KPI должны быть определены после пилотного внедрения на основе фактических данных.

## Вывод

Проведённый анализ показывает, что основные изменения TO-BE направлены непосредственно на факторы, связанные с увеличением длительности и сложности обработки заявок.

Наибольший потенциал улучшения имеют автоматическая маршрутизация, предварительная проверка данных и стандартизация процесса доработки.

Для подтверждения фактического эффекта после внедрения необходимо сравнить значения определённых KPI с показателями AS-IS.
