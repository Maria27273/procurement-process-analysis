# Procurement Process Analysis

## О проекте

Проект посвящён анализу и оптимизации процесса обработки заявок на закупку в компании.

Компания в рамках проекта является вымышленной, а все представленные данные — синтетическими. Данные были сгенерированы специально для демонстрации подхода к анализу бизнес-процесса и не содержат информации о реальных компаниях или сотрудниках.

В текущем процессе заявки передаются между сотрудниками по электронной почте, проходят несколько этапов проверки и согласования, а дальнейший маршрут зависит от типа закупки. Такой подход приводит к задержкам, повторной обработке заявок и сложностям с контролем их статуса.

**Цель проекта** - проанализировать текущий процесс, выявить основные проблемы и разработать вариант его оптимизации с использованием единой системы управления заявками.

## Что было сделано

* Проанализирован текущий процесс закупки и определены основные проблемы
* Определены заинтересованные стороны и их потребности
* Построена BPMN-модель текущего процесса (AS-IS)
* Разработана целевая модель процесса (TO-BE)
* Сформированы бизнес-, функциональные и нефункциональные требования
* Описаны основные сценарии взаимодействия пользователей с системой
* Разработаны UML-модели
* Создан набор данных из 5 000 заявок
* Проведён анализ данных с использованием SQL и Python
* Проведён Impact Analysis для сопоставления выявленных проблем и предложенных изменений
* Сформированы KPI для последующей оценки результата автоматизации

## Используемые инструменты

* **BPMN** — моделирование бизнес-процессов
* **UML** — моделирование системы
* **SQL** — анализ данных
* **Python** — подготовка, проверка и анализ данных


## Основные результаты

Анализ данных позволил выявить факторы, связанные с увеличением времени обработки закупочных заявок.

Наиболее существенная разница наблюдается между типами закупок:

| Тип закупки | Среднее время обработки |
| ----------- | ----------------------: |
| Простая     |                 9,96 ч. |
| IT          |                35,09 ч. |
| Юридическая |                58,35 ч. |

Также установлено влияние возвратов на длительность процесса: заявки с возвратами обрабатываются в среднем **48,06 ч.**, тогда как заявки без возвратов — **22,37 ч.**

Результаты анализа использованы для обоснования изменений в целевом процессе: автоматической маршрутизации заявок, проверки данных перед согласованием, автоматической передачи заявки между этапами согласования
