# Procurement Process Analysis

## О проекте

Проект посвящён анализу и оптимизации процесса обработки заявок на закупку в компании.

В текущем процессе заявки передаются между сотрудниками по электронной почте, проходят несколько этапов проверки и согласования, а дальнейший маршрут зависит от типа закупки. Такой подход приводит к задержкам, повторной обработке заявок и сложностям с контролем их статуса.

**Цель проекта** - проанализировать текущий процесс, найти основные проблемы и разработать вариант его оптимизации с использованием единой системы управления заявками.

## Что было сделано

* Проанализирован текущий процесс закупки и определены основные проблемы.
* Определены заинтересованные стороны и их потребности.
* Построена BPMN-модель текущего процесса (AS-IS).
* Сформированы бизнес-, функциональные и нефункциональные требования.
* Разработана целевая модель процесса (TO-BE).
* Описаны основные сценарии взаимодействия пользователей с системой.
* Разработаны UML-модели.
* Подготовлен Data Dictionary.
* Создан набор данных из 5 000 заявок.
* Проведён анализ данных с использованием SQL и Python.
* На основе результатов анализа сформированы предложения по оптимизации процесса.

## Используемые инструменты

* **BPMN** — моделирование бизнес-процессов
* **UML** — моделирование системы
* **SQL** — анализ данных
* **Python** — подготовка и анализ данных


## Основные результаты

Анализ 5 000 заявок показал существенную разницу во времени обработки закупок разных типов.

| Тип закупки | Среднее время обработки |
| ----------- | ----------------------: |
| Простая     |                 9,96 ч. |
| IT          |                35,09 ч. |
| Юридическая |                58,35 ч. |

Также было выявлено, что около **5–6% заявок проходят нестандартный маршрут**. Такие заявки в среднем обрабатываются примерно на **55% дольше** стандартных.

Полученные результаты используются для определения проблемных этапов процесса и обоснования изменений в целевой модели.
